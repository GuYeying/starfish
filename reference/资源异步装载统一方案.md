## 一、问题定义：三平台的"资源就绪"时序差

| 平台 | Device 创建 | 文件读取 | 解码 | 构造返回时 |
|---|---|---|---|---|
| 桌面 | 同步（pollster） | 同步（std::fs） | 同步 | **已就绪**（批次 31 已达成） |
| Android | 同步（pollster） | 同步（私有目录） | 同步 | 可同桌面——**但 base_dir 注入在 run 内**，run 前 io 路径错位（§五 修正项） |
| Web | **异步**（Promise） | **异步**（fetch） | 主线程同步（大图卡帧） | **Loading**（构造即返回句柄） |

统一目标：一套脚本零 cfg；行为一致——"构造返回句柄，就绪即可绘，
未就绪可查，失败可诊断"。

## 二、核心洞察：Texture 不需要"意图记忆"

设计稿 §4.3 的 `pending_play`（加载中调用 = 意图记忆，就绪自动执行）
是为 **Sound 的一次性动作**设计的：`play()` 只调一次，错过就丢了。

**Texture 的 draw 是逐帧重发的**——游戏循环每帧重画，本帧未就绪跳过、
就绪后下一帧自然出现，语义自动闭合。因此：

> **纹理不需要意图记忆、不需要中央行为队列。** 未就绪 draw = 本帧跳过
> （正常状态，对齐 base `InitSlot` 的"未就绪即跳过"哲学），就绪即绘。

这是本方案对设计稿 §4.3 的关键精简：三层机制里"对象层自治"瘦身，
"App 层登记"只剩可选的预算排水（§五）。

## 三、统一生命周期模型（三态句柄）

```
Texture(path)
  ├─ 桌面/Android：同步流水线 → 返回即 Ready（失败 = 构造抛错，即刻暴露）
  └─ Web：构造返回 Loading → spawn_local 流水线 → Ready | Failed
                                (device → fetch → decode → upload)
```

```
TexState = Loading | Ready { texture, bind } | Failed { msg }
```

- `draw()`：Ready → 记账；Loading → 本帧静默跳过；Failed → 确定性报错
  （脚本 bug 早暴露，不静默吞）
- `.ready` / `.error` pygetset——**加载屏模式**（设计稿 §三 定稿脚本的
  两相位生成器）：

```python
tex = pygame.render.Texture("wall.png")   # 桌面/安卓:返回即 Ready;Web:Loading

def game(ctx):
    if not tex.ready:                     # Web 才会真走到
        pygame.draw.clear(0.1, 0.1, 0.15)
    else:
        pygame.draw.clear(0.1, 0.1, 0.15)
        tex.draw((100, 100))              # Loading 期自动跳过,就绪自动出现
    yield
```

**三平台同一脚本，零 cfg。** 桌面的 `.ready` 恒真——加载屏分支自然退化
为不可达，无死代码负担。

## 四、Web 装载流水线（机制分解）

### 4.1 Device 异步创建（前置）

`ensure_device_slot` Web 版改造：`spawn_local(async_new_context)` →
完成后入 `DEVICE_SLOT`（web 版同槽）。构造期同步路径在 Web 不存在。

### 4.2 顺序保证：spawn_local 单队列 = 零额外机制

wasm-bindgen 的 spawn_local 任务**按入队序在同一线程顺序 drain**：

- Device 任务总是先于依赖它的纹理任务入队（构造器先 ensure 后入队
  自己的上传任务）→ 任务内查询槽位必然就绪；
- 纹理任务内部链条：`io::read(path).await → image::load_from_memory →
  create_texture/bind → 写回对象状态`——全部 await 点顺序自然成立。

**不需要回调链、不需要轮询、不需要锁**（RP 对象 Rc 同线程，spawn_local
闭包持 `PyRef<PyTexture>` clone 即可写回——'static 成立）。

### 4.3 写回

流水线闭包持句柄 clone；完成时 `*state.borrow_mut() = Ready(..)` /
`Failed(msg)`。对象无人引用则提前 drop，任务写回的是克隆句柄（RC 保证
存活）——与设计稿 §4.3"加载任务持 Py<PySelf>，写回槽位"同构。

## 五、修正项与已知边界

| 项 | 内容 | 处置 |
|---|---|---|
| **Android base_dir 注入时点** | 现在在 `run()` 内注入私有目录——run 前构造的 Texture 路径解析错位 | **修正**：注入提前到 `app_entry!` 捕获 AndroidApp 处（一行移位，io 单一事实源不变） |
